# Development Plan

## Overarching Goal

Ship a control plane, host agent, and relay that give short-lived workloads per-workload network identity across hosts in different places, with nothing on the path between two workloads able to read a packet. The design is in [SPEC.md](SPEC.md), which also holds every measurement; the positioning is in [README.md](README.md). This plan sequences the build and records what is proven.

The decisions the system makes — allocation, leases, policy compilation, the agent's ordering of kernel changes, the relay's admission of endpoints — run as deterministic code, proven in a simulator before they run against a real kernel, a real database and real sockets. The simulator follows `../s3-accelerator`: a seed draws the whole run, faults included, and replays it exactly.

v1 is deliberately smaller than the spec. These are designed and deferred:

- **`drain` mode and generation acknowledgment.** The spec already states this is not a lock, so narrowing the overlap window waits until a user needs it. Agents expose the generation they hold and the time each namespace took to converge, for observability.
- **Guest-owned keys.** The control plane already only ever sees public keys, so this needs no protocol change later.
- **Application health checking.** An interface joins a service when its lease is live and its agent reports the interface up.
- **A sharded or multi-region control plane.** One logical control plane over one transactional database; replicas share it.

The **device pool** has left the plan: creating a device straight into the workload namespace removes the namespace move, which was the only reason a pool was worth its bookkeeping.

## Implementation Principles

- **Decisions are deterministic; the daemons carry them out.** The packages that decide do no I/O, read no clocks, start no goroutines, draw randomness only from a source passed in, and iterate maps only in sorted order. They take requests, observed state and the current time as inputs and return actions. The control plane, agent and relay carry those actions out over Postgres, netlink, nftables and sockets; the simulator carries them out over its models. `internal/detcheck` enforces the rules as a test.
- **Storage is an interface.** The control plane reaches its database through `store.Store`: serializable transactions over typed records, with the lookups the control plane needs. Allocation, leases and compilation live once, above it. An in-memory store serves the simulator and unit tests, `pgstore` (pgx, queries generated by sqlc) serves production, and one conformance suite runs against both, so FoundationDB or MySQL slot in by passing it.
- **Create devices into the workload namespace, never create-then-move.** A device records the requesting socket's namespace as its socket's, so creating with `IFLA_NET_NS_FD` puts plaintext in the workload and ciphertext on the host with no move. Measured 621/s against 99/s at 64-way concurrency.
- **Know which netdev operations overlap.** A destroy defers its grace period past `rtnl_unlock` and scales 20× with concurrency; a namespace move holds RTNL across its own and scales 1.1×. Apply destroys concurrently; do not expect concurrency to rescue a move.
- **Peer work runs under RTNL: one lane per host, ~10–12k operations a second on a 4-vCPU cloud host and ~19k on a 24-thread desktop, not growing with cores.** `wg_set_device` holds `rtnl_lock()` for the whole call, so peer changes serialize against each other and against device, address, route and link work. Neighbour additions parallelize only across hosts. Raising the ceiling needs a kernel change; the userspace lever is grouping every pending change for a device into one call.
- **Budget a detach like an attach.** A single-peer removal waits two expedited grace periods under RTNL: 60µs on an 8-vCPU KVM guest, a quarter of an addition, but 90–100µs on a c6i.xlarge with Linux 7.0, the same as one. Each removed peer pays both even inside one call; a full flush shares one of them across every peer. Every expedited grace period interrupts every non-idle CPU on the host.
- **`persistent-keepalive` is set per path.** Relay peers carry none: the registration datagram registers each direction and holds the NAT mapping, so an idle peer costs nothing and two agents installing an edge at once do not collide on its first handshake. A co-located pair carries it on exactly one side, which keeps a session up and owns every rekey; two peers that initiate together stay in a failed-handshake lockstep. Direct paths keep it for their NAT pinholes.
- **The relay batches its syscalls.** `recvmmsg`/`sendmmsg` with `SO_REUSEPORT` sockets. A per-packet loop overflows its receive queue and carries less than a terminating gateway, which removes the reason to relay.
- **One relay port per direction.** The port a packet arrives on must name its sender. An address-based scheme cannot survive NAT that reassigns addresses, and cannot disambiguate two interfaces sharing one address at all.
- **Enforcement lives at the receiver.** `AllowedIPs` and nftables both run in the destination's kernel, one address per family per peer. Nothing a sender does to its own namespace may widen what it reaches.
- **Roaming owns the peer endpoint.** Any authenticated packet from a new source rewrites it, and the relay path depends on that. A reconciler that treats a roamed endpoint as drift will fight the data plane.
- **The agent mints keys and keeps them.** Private keys stay on the host — in the kernel device, never on disk — and the control plane sees public keys only.
- **Teardown follows the workload, not the control plane.** An agent holds its configuration through an outage of any length, because revocation runs through peers and costs nothing from the holder.
- **Every intermediate state is safe.** Order peer installation around the nftables transaction; a revocation skips the grace period that a planned removal uses.
- **Check every netlink call.** Discarding errors in a harness turned three failures into three published figures. The same mistake in an agent produces an interface that looks attached and is not.
- **Every component says what it is doing.** Structured logs through zerolog carry the network, service, interface, host and relay a line concerns; Prometheus metrics count every operation and time every stage a target in SPEC.md names.
- **Build the smallest implementation that meets the phase gate.** Add abstraction when a later phase needs it.

## Testing Strategy

- **Unit tests** for pure logic: allocation, the policy compiler, slot assignment, registration encoding, nftables rendering, resolver answers.
- **Simulator.** `cmd/wirenet-sim` runs a control plane, hosts with agents and a kernel model each, relays, an underlay with NAT, an orchestrator issuing changes, and workloads opening connections. Faults come from the seed: lost and delayed messages, partitions, NAT rebinding, agent crashes between any two kernel operations, relay and control-plane restarts, host reboots. Properties check the data plane against the orchestrator's record of intent, never against the control plane's own state. `go test ./...` runs a fixed seed range, CI runs the commit hash as a seed, and a phase ends with a local sweep of 10,000 seeds and no failures.
- **Regression seeds.** A bug the simulator finds becomes a test in `internal/sim` that runs its seed, with the seed and failing commit in the commit message. A seed replays its run exactly; each new source of randomness gets its own PRNG stream so existing draws stay unchanged.
- **Planted bugs.** `scripts/mutants` applies known bugs one at a time to a scratch copy and reports which layer catches each. Every behavior the spec names needs a test and a planted bug that the test catches. Every phase adds its own and must catch all of them.
- **The kernel model matches the kernel.** A root test drives the same operation sequences through the simulator's kernel model and through Linux, and compares what each reports: peer tables, allowed-IP ownership, endpoints, nftables maps. The simulator is only as good as this agreement.
- **Semantics run inside one Linux kernel, in CI.** Namespaces stand in for hosts: a relay in one, several hosts in others, each host handing a workload a namespace of its own, veth pairs for the underlay. This covers device placement, the slot table, convergence ordering, roaming on the return path, policy enforcement, and revocation. Root tests run through `go test -exec sudo`; `ubuntu-latest` on GitHub Actions is a full VM with root, kernel WireGuard and nftables.
- **Store conformance.** One suite runs against every `store.Store`: the in-memory store always, Postgres whenever `WIRENET_TEST_POSTGRES` names one (CI runs a service container).
- **An isolation claim needs a cannot-reach assertion in each family.** Every claim in SPEC.md under Trust needs a test that asserts a peer fails to reach something, not that a permitted flow works.
- **Performance figures need real hardware, and the substrate is not incidental.** Anything bound by an RCU grace period measured 2–3× apart between a KVM guest on 6.8 and a microVM on 6.18, in both directions. Record which substrate produced a number.
- **Measure the plain-TCP underlay ceiling in the same run.** Without it a throughput figure is meaningless: a path that reads as a design limit is often 95% of the network.
- **The relay-against-gateway comparison is the thesis regression test.** Both roles on the same machine against the same hosts, or it compares hardware rather than architectures.
- **Purge stray state between runs.** `ip netns del` only removes the name: a namespace a process still holds keeps its WireGuard device keepaliving and will claim a relay direction. One orphaned `iperf3` silently contaminated three consecutive runs.
- **`nft list` segfaults on a `jhash`-keyed map on nftables 1.0.9.** The ruleset works; the inspection tool crashes. Use `numgen random` until a newer `nft` is the floor.
- **Code review.** Each phase ends with `/code-review`. Findings are fixed or recorded in the phase ledger before the phase closes.

Execution order: Phase 0, then Phases 1 through 10 in order. Phases 1 and 2 share the simulator, so the agent's core runs against a scripted control plane in Phase 1 and the real one from Phase 2.

## Phase 1: Host agent, attach and detach against a local source

Goal:
An agent that attaches and detaches interfaces against desired state from a local source, with no control plane, proving the kernel path and the shape the API has to serve.

Scope:
- Mint a keypair, create the device into the workload namespace, key it, install peers, addresses and routes in each family, MTU.
- Install the nftables table and hand over a namespace without `CAP_NET_ADMIN`.
- Hold one netlink socket per namespace, opened inside it.
- Apply destroys through a concurrent worker pool; do not rely on concurrency for moves.
- Reconcile observed kernel state against desired state, including after an agent restart, and reclaim namespaces a process still holds.
- Peers on the same host take the loopback path, with `persistent-keepalive` on exactly one side, chosen by the lower interface ID. Single-host tests need no relay this way.
- The agent's decisions in a deterministic core (`internal/agent/core`), its kernel operations behind an interface with a Linux implementation and a simulator model, and an attach journal that makes every step restart-safe without writing a private key to disk.

Out of scope:
- Any control plane, lease renewal, or policy compilation.
- The stub resolver.

Completion gate:
At a policy degree of 20: attach reaches first packet in under 100ms against an already-converged peer, and a sustained attach-and-detach loop exceeds 100/s on a 4-vCPU host. Both are stated per degree because the peer lane bounds `attaches × degree`. An agent killed at any step of attach leaves no orphaned device or namespace after restart.

Testing plan:
- Assert the device's socket is in the host namespace and the workload namespace holds no underlay interface, verified by traffic rather than inspection.
- Assert a workload namespace cannot reach the underlay or another network.
- A churn test measuring attaches per second, which must fail if destroys become serial.
- A crash-recovery test: kill at each step, restart, assert convergence and no leaks, including a namespace held open by a stray process.
- Simulator: agent crashes between any two kernel operations; properties that no device or namespace is orphaned once the agent restarts, that no listen port leaks, and that keepalive is armed on exactly one side of each co-located pair.
- Kernel-model conformance for devices, peers, allowed-IP ownership and endpoints.

## Phase 2: Control plane, API and storage

Goal:
A control plane that stores the model and serves the desired state the Phase 1 agent reconciles against, over a storage interface that any transactional database can implement.

Scope:
- Resources for network, service, interface, lease, policy rule, relay, host, and directed edge-port allocation.
- `store.Store`: serializable read-write and read-only transactions over those records, retried on conflict, and a change notification so long polls wake. An in-memory implementation for the simulator and tests; `pgstore` on pgx with sqlc-generated queries, schema migrations, and Postgres `LISTEN`/`NOTIFY` for wake-ups.
- Address allocation, one pool per family, with IPv4 drawn only for services that opt in. IPv6 addresses are never reused within a network; IPv4 addresses are, with quarantine on the right clock: an address needs only the grace period plus convergence, provided each host removes the old peer and flushes its conntrack before a new peer claims the address; relay ports need to outlast stale senders, which makes them the scarcer pool. **Settling the quarantine length belongs here**, because allocation depends on it.
- Lease issue, renew, and revoke, accepting only public keys. Expiry waits out a grace period at least as long as the control plane's own downtime.
- The policy compiler: expand service-level rules into per-interface peer sets and address sets, each set emitted in every family the two services share.
- Desired-state push, batched per host rather than per namespace: an HTTP long poll on the host's generation, answered with every interface whose state changed since the generation the agent applied.
- The agent's control-plane client: attach, release, renew, and the long poll.

Out of scope:
- Generation acknowledgment for `drain` (deferred with `drain`).
- Multi-region or sharded control plane.

Completion gate:
A test creates two networks with overlapping address space, attaches four interfaces across two hosts, writes policy between them, and the compiled desired state for each host names exactly the peers policy permits and no others. A released address cannot be reallocated inside the quarantine window. The store conformance suite passes against the in-memory store and Postgres.

Testing plan:
- Unit tests for allocation, including exhaustion, quarantine, the service/interface split, and an IPv6-only service drawing nothing from the IPv4 pool.
- Unit tests for the policy compiler: sparse, fully connected, a rule naming a service with zero interfaces, and a rule between an IPv4-capable service and an IPv6-only one compiling to IPv6 alone.
- A test asserting a revoked lease disappears from every other host's desired state with no grace period.
- A test asserting the control plane never stores a private key.
- The store conformance suite, including conflicting transactions that must serialize.
- Simulator: the control plane in the loop with crashes, restarts and partitions; properties that no two live interfaces share an address, IPv6 is never reused, IPv4 and relay ports stay quarantined, and every host's kernel converges on the orchestrator's intent once faults stop.

## Phase 3: The relay in production shape

Goal:
A relay fit to run as a fleet: configured by the control plane, observable, and honest about its ceiling.

Scope:
- Take the pushed directed-port table from the control plane instead of trusting whoever arrives first.
- **The registration protocol, settled here rather than deferred.** An agent datagram carrying the direction, a counter, and a MAC over all of it plus the relay address and port, sent to the active relay and every standby. The key is derived per relay from the direction's secret, so a compromised relay cannot register at its peers. The counter derives from a clock at the agent and is persisted at the relay, so neither restart reopens replay or locks the agent out. The agent sends on underlay address change and on resume, with a 25-second floor, since on the relay path this datagram is the only thing holding the NAT mapping open. Binding the relay address stops cross-relay replay, and because the agent sends it, recovery does not wait on a WireGuard handshake. Admission and standby registration are one design, and Phase 3's gate depends on it.
- Relay persistence: the pushed port table, the per-relay registration keys, and the highest counter accepted per direction survive a restart.
- Per-port rate limits and metrics for forwarded, unroutable, rejected and write-failed packets.
- Multiple local addresses, so the table keys on `(local address, port)`.
- Agent-side relay probing and endpoint rewrite on failover, with both sides registered on every relay in the set.
- Every relay in a network's set carries traffic: each edge chooses its relay by hashing the edge with each relay among those its agent finds up, so a network's throughput grows with its relays and a dead relay's edges spread over the survivors.
- Relay peers configured without `persistent-keepalive`; the NAT-mapping test below shows the registration datagram holds the mapping.
- The relay's decisions in a deterministic core (`internal/relay/core`) that the simulator runs, with an attacker in the underlay sending to known ports and replaying captured registrations.

Out of scope:
- `sk_lookup` and XDP, which Phase 9 covers.
- Anycast relay addressing.

Completion gate:
On three machines in one datacenter the relay carries more traffic per CPU-second than a WireGuard-terminating gateway on the same box, with the underlay ceiling measured in the same run. Relay failover completes in under 1s. A direction cannot be claimed by a sender the control plane has not authorized.

Testing plan:
- The three-path comparison — direct, relay, gateway — as a committed benchmark, ceiling first. It records round-trip p50 and p99 on each path against the plain underlay's, both idle and while the throughput run saturates the path.
- A test asserting an unknown port and an unauthorized source are both dropped.
- A NAT test: a host whose public address and port change re-registers and traffic resumes.
- A NAT-mapping test, run in CI against a conntrack NAT built from namespaces: a registration datagram from a raw socket on the interface's listen port keeps the same mapping alive that WireGuard's own socket uses, so a relay peer with no keepalive still receives after the mapping's idle timeout has passed.
- An attach test: two agents install a new edge at the same moment, and the first packet arrives without losing a 5-second handshake round.
- A hijack test asserting an unauthorized sender cannot take over a live or dormant direction.
- A failover test measuring time from relay loss to resumed traffic on both sides.
- Spreading: both ends of an edge choose the same relay; a network's edges spread over its relays in proportion; a relay's loss moves only its edges, and over the survivors; aggregate throughput with one, two and three relays on EC2.
- Simulator: relay restarts, NAT rebinding and an attacker; properties that the relay forwards only from a direction's registered endpoint, never moves an endpoint on a data packet or a replayed registration, and forwards nothing to the attacker.

## Phase 4: Services, selection and convergence

Goal:
Services as the user-facing object, with a change that lands in one step per client and established connections that drain rather than break.

Scope:
- The fixed slot table, `typeof numgen random mod 1024 : ip daddr`, every slot filled, weight by slot count. An IPv4-capable service gets a second map in the other family, with every slot assigned to the same backend and both maps changed in one transaction. **Measuring the slot-map rewrite across many namespaces belongs here**, since the convergence gate depends on it; nftables commits take a per-namespace lock, so these can run in parallel even though peer work, which is on RTNL, cannot.
- Backend changes as element updates in one transaction, never a rule rebuild.
- Peer installation ordered around that transaction; revocation skipping the grace period.
- A service with no backends installing a reject rule rather than blackholing.
- `cutover` as the alternative to the default grace behavior.
- The stub resolver, with its listening descriptors handed across restarts so queries wait in the socket buffer rather than failing, and its state reloaded behind them. It answers A only where both the client's service and the target have IPv4.
- **Verifying the IPv6 nftables forms.** Every confirmed selection form is IPv4 (`ip daddr`), and IPv6 is the family every service has, so the `ip6 daddr` map declaration and `dnat ip6 to` translation are checked on nftables 1.0.9 before the slot table is built on them.

Out of scope:
- `drain` mode and generation acknowledgment.
- `jhash` affinity selection, until `nft list` stops crashing on a `jhash`-keyed map.

Completion gate:
Replacing a single-instance service flips every client in one step, with no client observing a partial backend set and no established connection broken. Convergence p99 in one region stays under 250ms with the slot-map rewrite included.

Testing plan:
- A test asserting a partially filled slot map is never written, in either family.
- A test asserting an IPv4-capable service's two maps assign every slot to the same backend.

- A test asserting no client reads a half-applied backend set under concurrent changes.

## Phase 9: Performance hardening

Goal:
Take the throughput levers the measurements identified, in the order their payoff warrants.

Scope:
- `sk_lookup` or an XDP relay data path, which the stated edge capacity requires.
- Underlay MTU probing per host pair, raising the overlay MTU where the path carries it.
- Direct paths: hole punching, endpoint rewrite, relay fallback.
- Measuring the loopback path against the relayed path for co-located interfaces.
- Control-plane write throughput: every write takes one revision row today.
- The cost of deleting a configured device, which sets detach latency.
- Per-edge relay subsets: each edge holds ports on its own few relays of a larger pool, chosen by the same hash, rather than on every relay a network names.
- Peering on demand: an edge's peers, relay ports and registrations built on its first packet rather than at attach, so allowed-but-idle pairs cost nothing.

Out of scope:
- Anycast relay addressing.

Completion gate:
Each lever is measured against the path it replaces on real hardware, with the underlay ceiling in the same run, and any that fails to pay is dropped from the design rather than carried.

Testing plan:
- `sk_lookup`/XDP against the batched userspace relay: pps per core, CPU per Gbit, and edges per process.
- MTU: throughput and CPU at 1380 against the discovered maximum, per path, noting that the lever is unavailable across the internet.
- Direct paths: latency and throughput against relayed, plus a fallback test when punching fails.
- Loopback: throughput and CPU against the relayed path for two interfaces on one host, plus a test that both workloads sending at the same instant after an idle period complete a handshake without falling into lockstep.

## Phase 11: Wildcard and deny rules

Goal:
A rule can name every service with `*` and can deny as well as allow, so a service opens itself to the rest of its network in one rule and exceptions carve flows back out, with the data plane enforcing exactly the flows the rules leave.

Scope:
- Rules carry an action, `allow` or `deny`, and either side may be `*`. `internet` stays a destination only.
- `*` never matches the service on the rule's other side. Traffic within a service needs a rule naming that service on both sides, because a service connected to itself costs a peer between every two of its members and opens lateral movement between them.
- A deny removes the flows it names from every allow, whatever the rules' order. Resolution is exact over TCP ports, UDP ports and every other IP protocol: `allow a -> b any` with `deny a -> b tcp/22` leaves TCP but port 22, all UDP, and every other protocol.
- The control plane resolves rules into concrete grants for each directed pair of services, and for each service's egress, when it compiles a network. A wildcard applies to services created after it. Peers, edges, slot maps, source sets, translations and egress all follow from the grants, so agents take the same compiled input, with one new protocol class, every protocol but TCP and UDP, which nftables matches as `meta l4proto != { tcp, udp }`.
- A pair whose grants are empty in both directions gets no peer and no edge. A pair allowed in one direction keeps its peers, and the denied direction loses only the receiver's accept.
- `GET /v1/networks/{net}/policy` and `wirenetctl policy NET` list the resolved grants.
- The API, CLI, memory and Postgres stores carry the action; Postgres takes a migration.
- A lab plan measures how long a deny takes to close every client under a wildcard, and how long removing it takes to reopen them, locally and on EC2.

Out of scope:
- Labels and selectors over services. A selector would follow the same self rule as `*`.
- An edge budget that refuses a rule whose resolved pairs exceed what the network's relays hold.
- An explain command naming the rules behind each grant.

Completion gate:
Wildcard and deny rules resolve exactly as SPEC.md states, the simulator's oracle evaluates them independently of the compiler and a 10,000-seed sweep passes, every planted bug is caught, the end-to-end suite asserts in each family that a denied flow and a wildcard's own service fail to connect, the policy plan runs on EC2 with its figures in SPEC.md, a high-effort code review's findings are fixed or recorded, and CI passes on the pull request.

- Unit: resolution of wildcards on either side and both, self exclusion and explicit self, deny overriding allow in full and in part, `any` less a TCP or UDP range, egress allows and denies, order independence, and agreement with a brute-force evaluator over random rule sets.
- nftables: the model and the Linux writer agree on the other-protocols class; a root test passes ICMP and refuses TCP through it in each family.
- Control plane and stores: validation, deduplication by action, the migration, and edges reconciled for a wildcard rule's scope.

## Phase 12: Registration races cost at most one handshake retry

Goal:
Every race between an agent's registrations, its relays and the control plane costs at most WireGuard's 5-second handshake retry, and none leaves a direction unregistered or a namespace waiting.

Scope:
- An agent that removes a relay peer withdraws its direction at every relay, above every counter it has sent, and resends the same bytes until each relay acknowledges them.
- Relays order claims and withdrawals by counter alone, durably.
- Acknowledgments carry their counter to the agent, and a slot's wait or a resend schedule counts only an acknowledgment above the counter it began at.
- A dormant edge changes nothing at its relays, so an agent cut off from the control plane keeps its directions registered; the epoch and its column go.

Out of scope:
- A claim whose every send is lost: its direction waits for the next periodic claim, up to 25s, as before.
- A clock that steps back across an agent restart (Phase 10).

Completion gate:
A relay test delivers every ordered subset of a run of claims and withdrawals and finds the highest counter deciding; agent tests cover withdrawal, resends, the acknowledgment floor and a peer restored mid-withdrawal; a planted bug for each mechanism is caught; the 10,000-seed sweep passes; the policy plan's figures are measured again locally and on EC2; a high-effort code review's findings are fixed or recorded; CI passes on the pull request.

Testing plan:
- Unit: the registration kinds; the relay's ordering over every sequence, and after a restart from its state file and from its log; the agent's withdrawals, resends and acknowledgment floors.
- Control plane and stores: dormancy keeps secrets; the migration that drops the epoch runs on Postgres.
- Simulator: 10,000 seeds, with acknowledgments carrying their counters.
- Planted bugs: each new mechanism.
- Lab: `wirenet-lab --plan policy` locally and on EC2.

## Phase 13: Named members

Goal:
A service's members can hold stable names, so software whose members address each other one by one, such as etcd or a database's replicas, runs as one service and keeps its configuration when a member moves to another host.

Scope:
- An attach may name a member of its service: a DNS label. `<member>.<service>.<network>.internal` resolves to the holder's own interface addresses wherever the service's name resolves, and in the holder's own namespace.
- At most one live interface holds a member name. An attach naming a held member fails with a conflict; `replace` revokes the holder and hands over the name in the same transaction. Only workloads hold names.
- A name frees when its holder's lease ends, by release, revocation or expiry, so a draining interface holds none.
- Members inherit their service's policy. Rules keep naming services, and the service address keeps spreading connections over every backend.
- The API, CLI, local agent API, memory and Postgres stores carry the member; Postgres takes a migration with a partial unique index over live holders.
- Listing interfaces shows each one's member, and an attach answer names the member's full name.

Out of scope:
- A stable address per member that outlives its holder, for software that caches a resolved address past its TTL.
- Rules naming a single member.
- SRV records listing a service's members.
- Members for gateways and development machines.

Completion gate:
Names resolve as SPEC.md states; the simulator draws members and replacements and its oracle checks every namespace's answers against the orchestrator's record; the 10,000-seed sweep passes; every planted bug is caught; the end-to-end suite asserts in each family that a member's name follows a replacement and that the replaced holder no longer reaches its peers; an etcd cluster keeps its data across a member moving hosts, locally and on EC2; a high-effort code review's findings are fixed or recorded; CI passes on the pull request.

Testing plan:
- Unit: label validation, the conflict, replacement in one transaction, a draining holder, an attach retried with `replace`, and the resolver's member records in each family and for the holder's own name.
- Stores: the holder lookup and the unique index, on memory and Postgres, and the migration.
- Simulator: the orchestrator attaches members and replaces holders on a stream of its own; the oracle checks that no two live interfaces hold one name and that each namespace's zone answers every member it reaches with its holder's addresses.
- Planted bugs: each rule above.
- End to end: three members resolve each other in IPv6 and IPv4; a replacement on another host moves the name; the replaced holder fails to reach a peer; a conflicting attach fails.
- Lab: `wirenet-lab --plan members` runs a three-member etcd cluster, moves one member to another host with `replace`, and measures how long the name and the cluster take to follow, locally and on EC2.
